How to use the protocol

Before you start

  • You need a DeepSeek account (chat.deepseek.com or the app) and the four copy cards below.
  • Use Notes or Google Docs to keep your filled-in and updated versions. This app does not save your changes.
  • Start a new chat in DeepSeek.

Step by step

  1. Fill in the Configuration record. Copy it into Notes and complete every field marked [REQUIRED]. The minimum: legal_name, jurisdiction, reporting_currency, industry, mission. Set registration_status to Pending. The contents differ for every entity.
  2. System prompt. Tap Copy system prompt and paste it into the chat. Before sending, replace [ENTITY NAME], [entity type], and [jurisdiction]. Send it and wait for the acknowledgment.
  3. Protocol core. Tap Copy protocol core, paste, send. It is long. If the chat has a limit, split it into 2 or 3 parts (for example Parts 1–14, then Parts 15–29). After the last part, type: Protocol Core loaded. Confirm receipt.
  4. Configuration record. Paste your filled-in version from Notes, not the blank one from the app. Send.
  5. Operating record. Tap Copy operating record, paste, send. In later sessions, paste your updated version from Notes instead.
  6. Activate. Type: Protocol, activate.
  7. First session. Try Founder briefing., What should I do next?, or Revenue review. The full command list is in Part 21 of the protocol.
  8. End of session. Type Update the operating record., then Produce session snapshot. Copy the output and save it in Notes. It becomes your operating record for the next session.
  9. Next session. Start a new chat. Repeat steps 2 to 5 using your updated operating record, then type Protocol, activate.

What activation should return

The expected response format: Executive Assessment, Recommended Decision, Council Findings, Immediate Action Plan, Founder Decisions Required, Risks and Blockers, Milestone Status, Continuity Record, and Founder Capacity Check.

This is not guaranteed. Responses vary by model and by run.

Keep in mind

  • Paste all four at the start of every new chat. The LLM has no memory between chats.
  • Do not skip the system prompt. It orients the LLM.
  • The operating record is your only continuous memory, so update it after every session.
  • If you did not save a snapshot, there is no record of the session.
  • Do not accept "done" or "saved" without confirmation. This is the protocol's core rule.

If something goes wrong

  • Not following the rules: type Refer to the protocol.
  • Inventing data: type Apply the evidence rules. Mark it CLAIMED or NOT ESTABLISHED.
  • Command not recognized: type Protocol, activate. again.
  • No response or cut off: split the paste into smaller parts.

Checklist

  • ☐ Configuration record filled in
  • ☐ Placeholders replaced in the system prompt
  • ☐ System prompt, protocol core, configuration record, and operating record pasted
  • ☐ "Protocol, activate." typed
  • ☐ First session started
  • ☐ Session snapshot saved
  • ☐ Operating record updated in Notes
